# Perfiles y zona de padres – Plan de construcción

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que cada niño tenga su perfil (progreso y ajustes propios, idioma incluido) en LecturAventura, con una pantalla «¿Quién juega?» y una zona de padres protegida donde se crean, editan, resetean y borran perfiles.

**Architecture:** La lógica de datos (crear/editar/borrar/resetear perfiles, validar, parsear lo guardado, candado, convertir perfil ↔ objeto `state`) vive en `src/profiles.js`, sin DOM y con pruebas en Node (objeto global `Profiles`, `module.exports` para Node). En `src/app.js` el objeto `state` sigue siendo un objeto plano con la forma actual, pero ahora es **una copia del perfil activo** (`Profiles.toState`); `save()` la escribe de vuelta en el perfil y guarda toda la tienda. Así el resto del código casi no cambia.

**Tech Stack:** HTML/CSS/JS puro (estilo ES5 con `var`, como `app.js`), `localStorage`, `node --test` (Node 22) para la lógica pura, `bash build.sh` para generar `index.html`.

**Spec:** `docs/superpowers/specs/2026-10-26-perfiles-design.md`

## Global Constraints

- Tras editar `src/`, siempre `bash build.sh` y commitear `index.html`. Pruebas: `node --test tests/*.test.js`.
- Sin dependencias nuevas ni `package.json`. Todo en `localStorage`; nada sale del dispositivo.
- Clave nueva `lecturaventura.save.v2`; la clave vieja `lecturaventura.save.v1` se **elimina** en el primer arranque (no se migra).
- Se empieza sin perfiles. «¿Quién juega?» se muestra **siempre**, aunque haya un solo perfil. Con cero perfiles explica que un adulto debe crear el primero.
- Máximo **8 perfiles**; nombre obligatorio, hasta **20** caracteres (tras `trim`), duplicados permitidos; avatar de un conjunto fijo de 12 emojis; idioma `es` o `en`.
- Ajustes por perfil (solo los cambia el padre): idioma, tamaño de letra (`small|normal|large`), tipo de letra (`standard|dyslexia|serif`), tema (`light|dark`), sonido (booleano). El niño ya no ve el engranaje de ajustes.
- Todo borrado/reseteo (perfil, progreso de un perfil, todo) pide confirmación (`confirm()`, como el código actual).
- Candado: multiplicación `a × b` con `a` entre 12 y 19 y `b` entre 3 y 9; si falla, se genera otra; sin bloqueo temporal.
- Idioma de las pantallas sin perfil activo: el del último perfil usado; si no hay, inglés si el idioma del navegador empieza por `en`, si no español.
- La práctica en voz alta solo aparece con `state.lang === "es"` (ya es así; no debe cambiar).
- Zonas táctiles ≥ 64 px (usar `.card`/`.btn`). Textos de interfaz en `UI.es` y `UI.en` de `src/content.js`, valores exactos en Task 3.
- Todo texto de usuario (nombres de perfil) que se inserte con `innerHTML` pasa por `esc()`.

## Review Focus

1. `localStorage` vacío, ilegible, con JSON corrupto, con la forma v1 o con perfiles incompletos: la app arranca con tienda vacía y no se rompe (Task 1, Task 3).
2. Nombre de perfil con HTML (`<img src=x onerror=alert(1)>`): se muestra como texto, no se ejecuta (Task 4).
3. Progreso aislado: lo ganado en el perfil A no aparece en B, al cambiar y volver A conserva todo; «Cambiar jugador» a mitad de historia o de práctica detiene temporizador y micrófono (Task 3).
4. Resetear progreso conserva datos y ajustes; borrar todo no resucita la partida v1 ni deja la app inutilizable (Task 5).
5. Límite de 8 perfiles y nombre vacío o solo espacios: mensaje claro, no se crea nada (Task 1, Task 4).
